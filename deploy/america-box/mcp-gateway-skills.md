# Skills catalog runbook (mcp.token118.com)

How the AI Gateway & Registry skills catalog is curated and operated. Sibling
runbook: [mcp-gateway-registration.md](mcp-gateway-registration.md) (MCP server
registration — shares the same Logto M2M credential source). Change of record:
`openspec` change `catalog-legal-skills-in-gateway` (archived under
`openspec/changes/archive/`).

## How skills work in the gateway

Skills are **URL references**, not hosted copies. Registering a skill = one API call
naming the upstream `SKILL.md` raw URL. At registration the gateway:

1. fetches and parses the agentskills.io frontmatter (name/description/version),
2. discovers companion resources (references/, scripts/, templates/…) in the same
   upstream directory via the GitHub Trees API,
3. hashes the content set as a drift baseline.

Ongoing behavior: `GET /api/skills/{path}/health` re-checks the upstream URL;
`GET /api/skills/{path}/integrity` compares the content hash against the baseline —
if the upstream repo changes files, `drift_detected: true` and the skill is
auto-disabled (fail-safe). Re-running the register action re-baselines and re-enables.

**Name policy (important):** the gateway rejects skill names that are not lowercase
alphanumeric with single hyphens (422 on anything else). Chinese-named skills are
registered under a translated English slug; the original name is preserved in
`metadata.name_zh` (visible via `GET /api/skills/{path}`).

entries. It was generated by walking the three repos (frontmatter parse + per-file
license rule); regenerate it the same way when upstreams change.

## Operating the catalog (on the america box)

Script: `/root/register_skills_gateway.py` (copy of
`scripts/infra/register_skills_gateway.py`; strip CRLF after copying from Windows:
`sed -i 's/\r$//'`). Credentials come from `/root/.mcp_logto_creds`
(`LOGTO_M2M_APP_ID` / `LOGTO_M2M_CLIENT_SECRET`) — same M2M app as the MCP server
registration (`mcpgatewaym2m` → `registry-admins`).

```bash
set -a; source /root/.mcp_logto_creds; set +a

python3 /root/register_skills_gateway.py show                    # list: name / visibility / license / status
python3 /root/register_skills_gateway.py show --name contract-review   # one skill, full detail

python3 /root/register_skills_gateway.py register                # all 85 (existing names update in place)
python3 /root/register_skills_gateway.py register --repo pa1nrui1/legal-skills
python3 /root/register_skills_gateway.py register --visibility group
python3 /root/register_skills_gateway.py register --name contract-review
python3 /root/register_skills_gateway.py register --dry-run

python3 /root/register_skills_gateway.py remove <name>           # delete exactly one skill
```

`register` is idempotent: it lists the catalog first and PUTs updates for existing
names (no duplicates), POSTs only new ones. Exit code is non-zero if any skill failed.

Long batches (the full 85 take ~10 min — the gateway fetches SKILL.md + resource
manifests per skill): run via `setsid nohup <cmd> > log 2>&1 &` and poll the log.
Note python block-buffers stdout to a file — the log stays empty until the buffer
flushes or the process exits; monitor `GET /api/skills?limit=1` `total_count`
instead for live progress.

## Verifying from outside the box

Mint an M2M token (any machine), then hit the public URL:

```bash
TOKEN=$(curl -s https://auth.token118.com/oidc/token \
  -u "$LOGTO_M2M_APP_ID:$LOGTO_M2M_CLIENT_SECRET" \
  -d grant_type=client_credentials -d resource=https://mcp.token118.com/api \
  | python3 -c "import sys,json;print(json.load(sys.stdin)['access_token'])")

curl -H "Authorization: Bearer $TOKEN" 'https://mcp.token118.com/api/skills?limit=100'
# expect: 85 total, 66 public + 19 group

curl -H "Authorization: Bearer $TOKEN" https://mcp.token118.com/api/skills/pdf-organizer/content
# expect: SKILL.md content JSON (frontmatter + body)

curl -s -o /dev/null -w '%{http_code}\n' https://mcp.token118.com/api/skills
# expect: 401 (unauthenticated)

curl -s -o /dev/null -w '%{http_code}\n' \
  https://mcp.token118.com/api/skills/contract-copilot/content
# expect: 401 unauthenticated; 200 with an admin token (registry-admins group)
```

Note on the visibility check: a non-admin *authenticated* principal was not
provisioned at verification time; enforcement rests on the `group` visibility +
`allowed_groups=["registry-admins"]` fields (verified in the catalog listing) and the
401 for unauthenticated access. When a non-admin user exists, repeat the restricted
content check with their token (expect 403/404, not 200).

## Upstream drift re-sync

If `integrity` reports `drift_detected: true` for a skill (upstream repo changed):

```bash
python3 /root/register_skills_gateway.py register --name <name>   # re-fetch, re-baseline
```

If the upstream restructure breaks the URL entirely (404 on registration), update the
`skill_md_url` in the `CATALOG` constant first. A drifted skill is auto-disabled, not
served stale — that is the intended fail-safe.
