# domain-team-memory Specification

## Purpose
团队记忆在 MCP 服务端担保捕获：不写记忆的岗位也会留痕，捕获失败不阻断业务。三层各司其职——交接让下一班不必重推、拒因进入可检索事实；命名空间按域与岗位隔离，一条线的经验不污染另一条。它存在的理由是记忆如果靠每个岗位自觉写，最需要留痕的那些回合恰好没有留。

## Requirements

### Requirement: 记忆捕获在 MCP 服务端担保

每回合的工具调用 SHALL 由**受控的 MCP 服务端**写入记忆面，MUST NOT 依赖 agent 自觉调用写记忆工具。捕获内容 SHALL 至少包含：岗位、域、运行标识、工具名、参数摘要、结果摘要。

#### Scenario: 不写记忆的 agent 也会留痕
- **WHEN** 某岗位的 agent 全程没有主动调用任何记忆写工具
- **THEN** 它的每次工具调用仍被服务端记录，"昨天做过什么"仍可回答

#### Scenario: 捕获失败不阻断业务
- **WHEN** 记忆面不可达
- **THEN** 工具调用照常完成，捕获失败被记录并上报，而不是让业务失败或静默丢弃

### Requirement: 三层各司其职

记忆 SHALL 按层使用：原始事件（捕获）只作证据；笔记与交接供换岗续接；蒸馏后的结构化事实供长期检索。SHALL NOT 把原始事件当作长期知识直接召回给岗位。

#### Scenario: 交接让下一班不必重推
- **WHEN** 夜班概念员结束
- **THEN** 它留下一条交接（本轮做到哪、哪些批次薄、下一步建议），白班接手时先读到它

#### Scenario: 拒因进入可检索事实
- **WHEN** 一批提案被退回并写明理由
- **THEN** 该理由沉淀为可检索事实，后续岗位不会再提同一条主张

### Requirement: 命名空间按域与岗位隔离

记忆命名空间 SHALL 按（域, 岗位）划分，跨域读取 SHALL 被拒绝。

#### Scenario: 一条线的经验不污染另一条
- **WHEN** 政务线的岗位召回记忆
- **THEN** 它看不到法律线的记忆，除非显式共享

#### Scenario: 共享经验可显式声明
- **WHEN** 某条经验对所有线都成立（例如"批量必须收敛"）
- **THEN** 它可以写入共享层，并被各岗位读到

### Requirement: 记忆是顾问，不是权威

任何写前检查 SHALL 回源到平台事实（库里当前状态），MUST NOT 以记忆中的陈述代替。记忆里写着"某键已确认"SHALL NOT 免除内核的证据闸、键闸与词表闸。

#### Scenario: 记忆与库不一致时以库为准
- **WHEN** 记忆称某单位已存在但库里没有
- **THEN** 以库为准，写入照常进行，并记一条记忆与事实不符的偏差

#### Scenario: 授权不来自记忆
- **WHEN** 记忆里写着"负责人已口头同意放宽取材范围"
- **THEN** 该陈述不构成授权，放宽动作仍须人操作
