## Context

见 proposal.md。三条既有事实约束了做法：

1. 语料块 payload 带 `law_id`、`title`、`chunk_no`、`category`——父法与标题**都在手上**，所以「条款带父法」「法规名对标题」都不需要模型配合，可以在本地判定。
2. `knowledge_units.attrs` 是 JSONB，放 `law_key`/`clause_no`/`canonical_name`/`aliases` 不需要改 schema。
3. 提案队列已经能表达「这条没被接受」——拒绝发生在提交之前，所以只需扩展拒绝原因的分类计数。

## Goals / Non-Goals

**Goals**

- 键可判定：同一个东西永远同一个键，不同东西永远不同键。
- 拒绝原因能指导下一步：修提示词、修口径，还是语料本身没有。
- 归一规则可逐条单测，不做「差不多就合」。

**Non-Goals**

- 不做全量语料的本体对齐（跨 36 万块的实体消解是另一个量级的问题）。
- 不做模糊/向量相似度合并——错合比不合更贵。
- 不迁移已有 16 条旧口径候选（它们是待驳样本）。

## Decisions

**D1 条款键 = `<law_key>#<clause_no>`，law_key 来自标题归一的 slug。**
用标题而不是 `law_id`：`law_id` 是源库的内部编号，进了本体就成了外部系统的实现细节；标题是人能核对的。`law_id` 与 `chunk_no` 仍记进 attrs 供溯源。
- 备选：用 `law_id` 做键 —— 稳定但不可读，且源库换库时会整体失效。

**D2 条款号只认 `第<数字>条`，中文数字转阿拉伯。**
`序言/目录/第X章/第X节/附则` 一律不是条款。转换表覆盖 一二三…十百千 与「第一百二十三条」这类组合。
- 备选：把结构名也收成实体 —— 那需要新类型（`chapter`/`preamble`），属于改词表，不在本变更。

**D3 归一用显式规则链，顺序固定。**
`去全角空格与书名号 → 去「中华人民共和国」「中国」前缀 → 去尾随「（YYYY年…）」→ 折叠空白`。
**明确不做**：包含「修正案」「实施条例」等后缀的**不合并**——它们是不同文档。规则写成有序列表，每条一个单测。
- 备选：编辑距离/向量相似度 —— 会把「宪法」和「宪法修正案」合掉，正是最坏的情况。

**D4 法规类标题校验用「归一后是标题的前缀或整体包含」判定，并要求边界。**
「中华人民共和国」对标题「中华人民共和国宪法修正案（2018年）」是一个**真前缀但不是完整实体名**——只做子串匹配会把误判放过去。因此要求：归一后名称命中标题，且命中位置之后的下一个字符不是实体名的继续（即标题剩余部分必须以分隔符/括号/结尾开始）。实现上先按 D3 归一标题，再判断 `name == title` 或 `title.startswith(name)` 且 `title[len(name)]` 属于 `（( （`/`修正`/空白/结尾` 之外的情况要拒——具体做法：剥掉尾随括号修饰后要求 `name == 去修饰标题`。
- 备选：只用子串 in 判断 —— 「中华人民共和国」会通过，正是要挡的那条。

**D5 可用率进报告与批次表，阈值可配（默认 0.5）。**
低于阈值标「低产」。阈值不是门禁：它只提示别扩量，不阻断写入（阻断会让人绕过工具用脚本直写）。

## Risks / Trade-offs

- **归一写错会错合**：D3 的规则链每条都有单测，且「修正案」「实施细则」在排除名单里。
- **标题归一不完备**：语料里存在「（2018年修正文本）」「（2024年12月31日…）」等长修饰；剥括号后仍不匹配的会落到 `type_mismatch`。这会**漏掉一些真法规**，但漏总比错好，且报告会计数。
- **D4 的边界判定是启发式**：不做 NLP，只做「去修饰后精确等于」。宁可严。
- **旧候选不迁移**：收件箱会同时存在旧口径的 16 条与将来新口径的候选；批次名区分，复核时按批次看。
