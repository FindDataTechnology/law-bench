# 域归档验收（2026-11-09，镜像 `sha-58e7d4b`）

## 问题

全仓 grep 不到 `DELETE FROM domains`，`domains` 也没有软删列——**建错一个域就永久
占着运营台一行**。在鼓励「快速填充很多细分域」之前，先得让建域可撤。

## 生产闭环实测（真库）

用一个探针域 `archive-probe` 跑完整回路：

```
归档前      listed = True
归档后      listed = False | 归档视图可见 = True | 知识单元仍在 = True
缺口矩阵    该域行数 0（默认视图不含归档域）
key 复用    被拒（报错含 "archived"）
恢复后      listed = True | 知识单元仍在 = True
```

探针域最后留在归档状态：数据保留，不占名录。

## 设计取舍

- **只用 `archived_at` 一个列**：归档只写时间戳，恢复只清空它，其余列逐列不变（单测
  逐字段比对）。所以两个动作在任何时刻都可互退，不需要数据修复。
- **不级联、不取消订阅**：归档语义是「暂不干这条线」，不是「清掉这条线」；恢复后
  订阅、成员、单元、rubric、提案原样生效。
- **过滤点只有一个**：`list_domains`（名录/切换器/缺口矩阵共用）。六个调用点各自
  过滤会漂成六种口径。
- **key 不释放**：历史记录（提案、运行、事件）里的 key 必须永远指同一个域；复用会
  把两代域的历史混在一起。
- **权限与建域同门**（平台 admin）：域 lead 自行退场会让平台以为它健康。
