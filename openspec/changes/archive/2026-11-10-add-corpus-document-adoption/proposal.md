# 从大库取文档进本体（Corpus Document Adoption）

> 蓝图台账 **C6**。前序：C5 `add-domain-first-workbench`（域优先工作台）、`add-legal-concept-layer`（概念层）、`add-ontology-extraction-candidates`（抽取候选）。

## Why

本体域已经能「收」内容（创作台、抽取候选、批量导入），但**取材这一步没有门**：库里躺着 364,916 个法规语料块（`law-library`），其中 34,010 份文档，而本体里只有 4 部法规、15 个概念、1 条条款。人想知道「库里有哪部法、我要哪几部、某部法的第 585 条写了什么」，只能在检索框里瞎搜。

这不是流程问题，是**结构缺失**：

- **库的结构不可见**。`law-library` 的 7 个来源按 `category` 过滤（法律/行政法规/司法解释/地方性法规/规章/…），文档标题、状态、发布日都在 payload 里，却没有一个界面按文档列出它们。库里 34,010 份文档对用户等于 0 份。
- **概念挂不上法条**。上一轮实证：概念抽取产出的 `defines` 关系被计为 `bad_endpoint`，因为目标条款单位不存在。条款单位不存在的根因不是抽取不行，而是**没有一条从语料里取条款的路径**——手工录 364,916 条不现实。
- **「大库 → 子域取材」这条既定架构没有实现**。用户已裁：行业知识做一个大库，子域从中取材做特殊处理。大库有了（`law-library`），子域也有了（`legal`/`gov`），中间那一步「取材」缺失。
- **LLM 抽取不是取材的手段**。抽取适合从无结构的裁判说理里推概念；而法规文档名、条款号、条文本身**就在语料里逐字写着**，让模型去「抽」只会引入编造风险。取材应当**确定性地读**，不经过模型。

## What Changes

1. **语料文档目录（只读派生，不落新表）**：`/d/{key}/library` 把域订阅来源里的文档按**文档**列出——标题、类别、法规类型、发布日、状态、语料块数；支持按来源过滤、按标题搜索、分页。目录**实时派生**自存储，不落表，因此不可能与库漂移。
2. **来源自述文档结构**：一个来源怎么从自家 payload 里读出「文档/标题/正文」由 `library_sources.ingest_rule` 声明（与既有 `columns` 映射同一处、同一机制），内核不写死任何域的字段名。
3. **取文档进本体**：选中一份文档 → 经内核 `authoring_create_unit` 落一条 `law` 单位，键沿用既有归一规则，`attrs` 记 `law_id`/`source_key`/`chunks`/`publish`/`status`，证据是该文档自己的语料块。幂等：同键重复取回同一单位。
4. **取条款进本体**：对已取入的文档，**确定性切分** `第N条` → 每条一个 `clause` 单位，键 `<law_key>#<N>`，`body` 是条文原文（逐字，不概括），证据是承载它的 `chunk_id`。跨块条文按 `chunk_no` 顺序拼接；拼不全就 `attrs.truncated=true`，不许假装完整。
5. **概念落地**：条款单位存在后，抽取的 `defines` 候选才有合法端点——这条链闭合，不需要新的抽取逻辑。

## Capabilities

### New Capabilities

- `corpus-document-catalog`: 语料文档目录——按文档（不是按块）列出一个域可取材的范围，来源自述文档结构，派生不落表，不可达的库报错而不报零。
- `corpus-document-adoption`: 取材契约——从目录取文档/条款进本体，只走内核写路径，键沿用既有规则，切分确定性可复核，截断如实标记，批量有上限且说明被跳过的原因。

### Modified Capabilities

- `ontology-key-scheme`: 增加「语料文档键」到既有条款键之间的衔接约束——从语料切出的条款键必须与既有 `<law_key>#<clause_no>` 完全一致（不许出现第二种条款键形状）。

## Impact

- 代码：新增 `src/bench/corpus_catalog.py`（读派生目录 + 确定性切分）；`src/web/routes/console.py` 增加 `/d/{key}/library` 浏览/取用路由；新模板；`src/bench/libraries.py` 的 `ingest_rule` 增加 `document` 映射解析。
- 数据：`library_sources.ingest_rule` 为 `law-library` 的 7 个来源补 `document` 映射（一次 `UPDATE`，可回滚）；取入的单位经人工在页面上点击才产生，不自动灌数据。
- 不改：抽取逻辑、模板词表、发布/分发契约、检索路径。
- 风险：34,010 份文档里地方性法规与规章占大头（166k+117k 块），目录默认按来源分组而不是一次全列；条款切分对「一法一条」型决定类文档（`修改、废止的决定`）会切不出条款，如实报 0 而不是造。
