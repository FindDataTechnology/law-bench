## Why

The repo ships 41 contract 母版 (`src/contracts/data/contracts.json`, one Markdown `body` per contract class with `{{slot}}` placeholders) generated by `scripts/seed_contract_templates.py` and refreshed by `scripts/generate_contract_templates_llm.py`. The **only** completeness check today is `check_slot_consistency()` in `src/contracts/slots.py`, which compares a template's slot set against its per-type `slot_instructions` manifest (missing-vs-extra instructions). It never gates against the canonical `REQUIRED_SLOTS` set, does not grade *where* a slot appears, and is not exposed as a CLI or report — so the user's premise ("many 母版 lack 甲方/乙方/时间 slots") is invisible until generation time.

Worse, `normalize_body()` actively **masks** the gap: when an LLM-drafted body omits a required slot, it appends that slot to a trailing `## 签署信息` block. A slot can therefore be "present" yet semantically misplaced — confirmed by inspection, all 41 templates have `sign_date`/`sign_location` appearing *only* in that tail block, and `party_a`/`party_b`/`term_*` could be silently papered over the same way on the next regeneration. There is no tool that answers "which 母版 are genuinely well-formed, and which are missing the slots a fillable contract needs?" This change adds that evaluator.

## What Changes

- **New deterministic slot-coverage evaluator** over contract 母版 (no LLM, no DB — hermetic and fast): for each template, checks presence of every `REQUIRED_SLOTS` entry (甲方 `party_a`, 乙方 `party_b`, 时间 `term_start`/`term_end`/`sign_date`, etc.), flags slots missing entirely vs. present-but-only-in-the-`签署信息`-tail (semantic misplacement), flags slots in the body that lack a `slot_instructions` entry, and computes a per-template pass/fail + coverage score plus an aggregate summary.
- **New CLI**: `python -m src.contracts audit [--type <key>] [--json] [--strict]` added to `src/contracts/cli.py`. `--strict` exits non-zero when any required slot is missing or misplaced, so it can gate CI / the template-regeneration script. `--json` emits the structured report; default prints a human-readable table.
- **Generator integration**: `scripts/generate_contract_templates_llm.py` runs the evaluator on the **raw** LLM output *before* `normalize_body()` and logs which slots the drafter omitted (so normalization no longer silently hides draft quality); the committed registry is still normalized as today.
- **Report artifact**: an optional `output/contract_slot_audit.json` snapshot written by the CLI, suitable for diffing template quality across regenerations.

## Capabilities

### New Capabilities
- `contract-template-slot-eval`: a deterministic evaluator that audits contract 母版 (`src/contracts/data/contracts.json`) for slot completeness — presence of every canonical `REQUIRED_SLOTS` entry, semantic placement (not merely appended to the `签署信息` tail), and instruction-manifest coverage — and exposes the result as a Python API, a `python -m src.contracts audit` CLI (human table + `--json` + `--strict` gate), and a JSON report artifact.

## Impact

- **New code**: `src/contracts/audit.py` (evaluator core + report model); a new `audit` subcommand in `src/contracts/cli.py`; report writer for `output/contract_slot_audit.json`.
- **Modified code**: `scripts/generate_contract_templates_llm.py` (call the evaluator on raw LLM output pre-`normalize_body`, log omissions as warnings — non-blocking; behavior of the committed registry unchanged).
- **New tests**: `tests/test_contract_slot_audit.py` — hermetic (no LLM, no DB, no network): synthetic template bodies asserting present/missing/misplaced/extra classification, coverage score, `--strict` exit code, and JSON report shape; plus a regression test that the current 41-template registry passes the required-slot presence gate.
- **Dependencies**: none new — reuses `src.docs.SLOT_PATTERN`, `src.contracts.slots.REQUIRED_SLOTS` / `default_slot_instructions`, and `src.contracts.templates.get_template`.
- **Out of scope**: LLM-judge quality scoring of clause prose (owned by `evaluation-rules`); auto-rewriting templates to fix gaps; a web UI for the audit (deferred follow-up); auditing clause-assembled contracts from `src/clauses/` (separate assembly path).
