## Why

The finetune-data-flywheel change shipped a read-only extraction over **6 warehouse tables** and the bronze/silver guards — but the live warehouse holds **~14 more tables**, several of which are exactly the material the flywheel is gated on. The flywheel order gate is currently **shut**: Judge-C gold is 0 quadruples, so Drafter reward modeling cannot start. Meanwhile the silver warmup pool is ~59% duplicates (363 non-null `filled_text` → only **151 distinct bodies**), and the design's open question "法条原文从哪拉" has a candidate answer (`law_info`, 86 rows) that turns out to be **LLM-generated**, not authoritative. The biggest in-house unlock — `type_validations` (275 unique compliance rules, **258 with explicit `law_ref`**, across 49 contract types) — was never extracted. This change widens extraction to the high-value skipped tables, dedups the silver pool, and turns `type_validations` + `clauses` + `law_info` into a pre-scaffolded Judge-C annotation substrate so human review produces gold quadruples at tractable cost — which is the only thing that actually opens the gate.

## What Changes

- **Widen warehouse extraction** to five previously-skipped tables, each tagged to the right tier:
  - `type_validations` (275 rules, 258 w/ `law_ref`) → **gold-tier criteria scaffold** (rule + law_ref + violation message; human verifies before promotion to gold quadruple).
  - `law_info` (86) → **bronze** (LLM-generated by doubao/deepseek; retrieval aid only, never ground-truth law text).
  - `contract_artifacts` (362) → **raw** drafter skeleton source (template bodies w/ `{{slot}}` placeholders, cleaner than LLM-filled `pipeline_runs`).
  - `core_clauses` (22) → **gold** mandatory-clause checklists per type.
  - `industry_standard_references` (22) → **gold** statute pointers per type.
- **Dedup the silver pool**: 363 non-null `filled_text` collapse to **151 distinct bodies**; the Drafter-A silver export emits unique pairs only (was 306 incl. duplicates).
- **Add a Judge-C candidate-quadruple builder**: pairs each `type_validations` rule (carrying `law_ref`) with candidate clause bodies from `clauses` (same `contract_type`) + the law text from `law_info` (as a *retrieval hint*, not the label), producing a **silver-tier scaffold** quadruple that a human reviewer verifies into gold. This does not auto-promote anything — it shrinks the per-quadruple annotation cost from blank-page to verify-and-correct.
- **Tier the new sources through the existing single-point guard**: `law_info` and any LLM-generated scaffold stay bronze/silver (never ground truth); only human-verified output is gold. The bronze/silver guard in `common.py` already covers this; the new builder routes through it.
- **Open-source intake stays gated but gets a relevance audit**: CAIL2018 is criminal judgment prediction (off-task for contract drafting); document its role as **adjacent legal-reasoning warmup only**, not contract-compliance signal. Keep the {Apache-2.0, MIT} gate as-is.

## Capabilities

### New Capabilities

- `finetune-data-flywheel`: (introduced by the prior `add-finetune-data-flywheel` change, not yet synced to main specs) read-only warehouse extraction, license-gated open-source intake, four-tier data model with bronze/silver guards, Judge-C quadruple + Drafter-A pair datasets, and the flywheel order gate. This change's delta spec extends it with widened extraction sources, silver dedup, and the candidate-quadruple scaffold builder.

### Modified Capabilities

_(none — `finetune-data-flywheel` is not yet in `openspec/specs/`, so this change carries it as a new capability with the full requirement set including the extensions.)_

## Impact

- **Read-only extraction widens** from 6 to 11 tables; still pure `SELECT` + disk, zero writes to existing tables. New tables are read-only sources only.
- **`scripts/finetune/extract_warehouse.py`**: add the 5 tables to `TABLES` + `TIER_BY_TABLE`; the existing tier-tagging + idempotent JSONL path handles them without structural change.
- **`scripts/finetune/export_dataset.py`**: add silver dedup (by `filled_text` hash) to `_build_silver_pairs`; add a `judge-c-scaffold` subcommand that emits candidate quadruples from `type_validations` × `clauses` × `law_info`.
- **`data/finetune/judge-c/`**: new `judge_c_scaffold.jsonl` (silver-tier, machine-generated candidates) alongside the existing bronze/gold files. Guard prevents scaffold from being used as ground truth.
- **`docs/finetune-data.md`**: update the table/tier map, the real silver-pool number (151 unique), and the `type_validations` scaffold flow.
- **No DB schema changes, no runtime behavior changes** to the existing `generate → fill → evaluate → check → improve → store` pipeline. Rollback = delete new extraction outputs + revert the script changes; existing tables untouched.
- **Open-source gate unchanged**; CAIL2018 reclassified in docs as adjacent-warmup-only (no code change to the gate).
