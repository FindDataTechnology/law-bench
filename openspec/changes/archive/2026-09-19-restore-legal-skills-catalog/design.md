# Design: restore-legal-skills-catalog

## Context

See proposal.md — Why. What exists today:

- `scripts/infra/register_skills_gateway.py`: stdlib-only automation with an embedded
  85-entry `CATALOG` (66 public + 19 group, pinned 2026-08-30), actions
  `register`/`show`/`remove`, M2M client_credentials auth. Its default gateway env
  (`MCP_GATEWAY_URL`) already points at `https://mcp.finddatatech.cloud`; credential
  fallback `/root/.mcp_logto_creds` is america-era and dead — on cheap1 the creds live
  in `/opt/mcp-gateway-registry/.env` as `LOGTO_M2M_CLIENT_ID`/`LOGTO_M2M_CLIENT_SECRET`
  (the README's MCP-registration section shows the `LOGTO_M2M_APP_ID` export mapping).
- `cmd_register` is idempotent by name: it lists existing skills, PUTs (updates) for
  known names, POSTs new ones, with a 409/400 → PUT fallback. It does **not** check
  that an existing name maps to the *same upstream skill* — a second catalog entry
  reusing a name would silently overwrite a different skill.
- The M2M channel (`mcpgatewaym2m` → `registry-admins` incl. skills scopes) and the
  Mongo `idp_m2m_clients` mapping are live on the cheap gateway (proven by the
  law-bench MCP server registration, 2026-09).
- The gateway's skills feature is URL-reference based: it fetches the upstream
  `SKILL.md` from raw.githubusercontent.com (public internet — not affected by the
  CGNAT SSRF allowlist), discovers companion resources via the GitHub Trees API, and
  hashes content as a drift baseline (auto-disable on upstream change).
- The original catalog was generated by a **manual repo walk** (no committed
  generator): frontmatter parse + per-file license rule → pinned Python entries.
  Same approach is reused for THUYRan.

## Goals / Non-Goals

**Goals:**

- 85 original skills listable again on `mcp.finddatatech.cloud`, original visibility
  split intact.
- 38 (expected; exact count pinned at generation) THUYRan skills registered
  group-restricted, served verbatim, with CC BY-NC-ND recorded per skill.
- Registration cannot silently overwrite a different skill via a name collision.
- An operator on cheap1 can run register/show/remove and re-sync after drift purely
  from the new cheap-box runbook.

**Non-Goals:**

- No gateway-side changes (deployment, config, auth) — the skills API is used as-is.
- No generator script for the catalog (manual walk, matching the original method).
- No skill-content adaptation (ND forbids it) and no law-bench tool wiring (see
  proposal Out of scope).
- No public promotion of NC/NC-ND skills.

## Decisions

### D1: Restore the 85 as-is — no regeneration

The pinned 2026-08-30 catalog is re-registered unchanged. If an upstream repo moved
since the pin, register re-fetches and re-baselines at today's content — that is the
desired behavior, and drift auto-disable covers anything that breaks. Regenerating
the 85 would re-litigate curation decisions for no behavioral gain.
*Alternative rejected*: regenerate all four repos uniformly — more work, changes
names/metadata that the runbook and muscle memory already reference.

### D2: THUYRan onboarding = manual walk → CATALOG entries, license-verified

Walk `THUYRan/Legal-Skills-Chinese` (GitHub API or shallow clone), resolve each
`SKILL.md` raw URL, verify frontmatter + the CC BY-NC-ND 4.0 declaration, then append
pinned entries: `visibility=group`, `allowed_groups=["registry-admins"]`, tags
`legal`/`chinese-law`/`thuyran`, `metadata.source_repo` set so `--repo` filtering
works. All skills in this repo are legal-reasoning skills — the non-legal exclusion
rule is expected to drop nothing, but the walk still applies it. If any skill's
license is absent or ambiguous, that skill is **excluded and noted** (no grant → no
registration), not guessed.
*Alternative rejected*: repo-level blanket license without per-file check — the
original three repos taught us licenses vary per skill file.

### D3: Collision safety in two layers (fail closed)

1. **Static**: at startup, duplicate `name`s within `CATALOG` abort the script
   (`sys.exit`) before any network call.
2. **Runtime**: in `cmd_register`, before the PUT-update branch, compare the existing
   gateway entry's source URL (`skill_md_url` if the listing exposes it — verify in
   the smoke test; otherwise `GET /api/skills/{path}` detail) with the catalog
   entry's. A name held by a *different* upstream URL is reported as a collision:
   that entry is skipped, the existing entry is left untouched, and the run exits
   non-zero. THUYRan name clashes with the existing 85 are resolved **by hand at
   catalog-build time** (disambiguate with a `thuyran-` prefix, keeping
   `metadata.name_zh`/original dir in metadata).
*Alternative rejected*: automatic prefixing on collision — silent renames hide the
conflict and confuse drift mapping; the spec's fail-closed scenario wants visible
errors.

### D4: `remove` gains `--repo` / `--visibility` filters

Reuses the existing `_select` machinery so the THUYRan set (and any repo subset) can
be rolled back with one command instead of 38 name-by-name removes. Behavior
otherwise unchanged (`remove <name>` still works, still deletes exactly one skill).

### D5: Runbook at `deploy/cheap-box/mcp-gateway-skills.md`

Adapted from the america runbook with cheap specifics: script copy + CRLF strip,
credential sourcing from `/opt/mcp-gateway-registry/.env` (export mapping), the M2M
Mongo-mapping prerequisite note (already satisfied — point at the README section),
long-batch handling (123 skills ≈ 15 min: `setsid nohup` + poll
`GET /api/skills?limit=1` `total_count`), drift re-sync, THUYRan ND policy
(verbatim + group-restricted + authorization-gated public promotion), and the
expected end-state counts (123 = 66 public + 57 group). The america-box runbook
stays untouched (immutable history per AGENTS.md); the cheap-box README gateway
section gets a one-line pointer.

### D6: Execution order — smoke, restore, verify, extend, verify, document

Cheap gateway runs the same registry software but a possibly newer version; skills
endpoints specifically have only been exercised on america. So: (1) verify API shape
+ one throwaway-skill register→show→remove cycle against the live cheap gateway;
(2) register the 85, verify; (3) build + review THUYRan entries, register, verify;
(4) runbook + README pointer. Each stage is independently rollback-able via
`remove`.

## Risks / Trade-offs

- [Cheap-gateway skills API differs from america-era shape (fields, visibility
  semantics)] → D6 stage 1 smoke test catches it before any batch; adjust payload
  mapping only, no design change expected.
- [THUYRan license not actually declared per-file/repo] → D2 excludes-and-notes
  rather than registering on assumption; the extension degrades to a restore-only
  change.
- [Gateway listing lacks the source URL needed for the runtime collision check] →
  fallback per-entry `GET` detail (one extra call per updated skill, acceptable at
  this scale).
- [Non-admin invisibility not directly testable] → we hold only an admin M2M
  channel; verification confirms `visibility=group`/`allowed_groups` on the entries
  and relies on the gateway's group enforcement (same posture the america change
  documented). Recorded as a runbook note.
- [Upstream drift since the 2026-08-30 pin auto-disables skills right after
  restore] → re-running register re-baselines; the runbook makes this a routine
  re-sync, not an incident.
- [Batch runtime grows to ~15 min] → nohup + `total_count` polling per the runbook;
  register remains per-skill idempotent so interruption is safe to re-run.

## Migration Plan

1. Script changes (D3 static check + runtime collision guard, D4 remove filters) —
   pure additions, unit-checkable by import/dry-run.
2. Smoke test on cheap gateway (throwaway skill) → restore 85 → verify counts and
   visibility split (66/19).
3. THUYRan walk → pin 38 entries in `CATALOG` → register → verify (66 public / 57
   group; total 123).
4. Runbook + README pointer; validate change.

Rollback: `remove --repo THUYRan/Legal-Skills-Chinese` undoes the extension; the
restore set is removable by repo/visibility filters the same way. The gateway has no
other state to unwind.
