## Context

当前评价体系包含 82 个评价规则（41 种合同类型 × 2 个版本 v1/v2），每个规则由 4 个通用基础标准（party_identification, governing_law_present, clause_completeness, legal_citation_accuracy）和 5-7 个类型特定标准组成。

**当前问题：**
- 具名合同（19 个）和非具名合同（22 个）使用同一套通用标准框架
- 通用标准过于严格：要求单独的"适用法律"条款、精确的法条引用（如"法释〔2020〕17 号"）
- 测试结果显示平均通过率仅 31%，非具名合同普遍面临"适用法律"条款缺失问题
- capital_increase 等类型 0% 通过率，可能是条款库缺失而非评价标准问题

**约束条件：**
- 必须保持向后兼容，不能破坏现有的 v1/v2 评价规则
- 需要支持增量迁移，允许逐步重构
- 必须保持评价的可测试性（每个标准都有明确的判定逻辑）

## Goals / Non-Goals

**Goals:**
- 为具名合同和非具名合同建立差异化的评价框架
- 优化通用标准的合理性，降低不必要的严格性
- 为非具名合同建立行业标准参照机制
- 提升整体评价通过率到 50% 以上（当前 31%）
- 保持评价的可测试性和一致性

**Non-Goals:**
- 不改变评价引擎的核心算法（仍使用 LLM judge）
- 不修改 v1 版本的评价规则（保持向后兼容）
- 不引入新的评分阈值机制（维持绝对阈值）
- 不改变 rubric 的数据库 schema（仅修改标准内容）

## Decisions

### Decision 1: 差异化标准框架

**选择：** 为具名合同和非具名合同分别设计评价标准框架

**理由：**
- 具名合同有明确的民法典法律依据，可以制定严格的法定必备条款标准
- 非具名合同缺乏法律规定的标准框架，需要灵活的行业标准参照
- 混合使用同一套标准导致非具名合同通过率普遍偏低

**替代方案：**
- 统一标准 + 场景化补充：保持通用标准，为不同场景添加补充标准
- 完全统一：所有合同类型使用完全相同的标准

**拒绝原因：** 统一标准无法解决非具名合同的特殊性问题；完全统一会丢失类型特定性

### Decision 2: 通用标准优化策略

**选择：** 采用分层判定机制（PASS / HALF_PASS / FAIL）替代二元判定

**理由：**
- 当前二元判定（PASS/FAIL）过于严格
- 很多合同在"鉴于"部分已经引用了法律，但没有单独的"适用法律"条款
- 分层判定可以区分"完全符合"、"部分符合"和"完全不符合"

**替代方案：**
- 保持二元判定但放宽要求
- 引入加权评分机制

**拒绝原因：** 放宽要求会丢失标准的严格性；加权评分增加复杂度

### Decision 3: 行业标准参照机制

**选择：** 为每个非具名合同领域建立行业标准参照表

**理由：**
- 非具名合同缺乏法律规定的必备条款
- 行业标准可以提供实用的评价依据
- 参照表可以持续更新，保持灵活性

**替代方案：**
- 专家评审机制：人工制定每个合同的评价标准
- 商业合理性导向：仅评估合同是否满足交易目的

**拒绝原因：** 专家评审成本高、不可扩展；商业合理性过于主观

### Decision 4: 迁移策略

**选择：** 增量迁移，先创建 v3 版本，逐步替换 v2 版本

**理由：**
- 保持向后兼容，不破坏现有系统
- 允许逐步验证新标准的效果
- 可以快速回滚到 v2 版本

**替代方案：**
- 一次性替换所有 v2 版本
- 并行运行 v2 和 v3 版本

**拒绝原因：** 一次性替换风险太高；并行运行增加维护成本

## Risks / Trade-offs

**Risk 1: 新标准可能仍然过于严格**
→ Mitigation: 通过 A/B 测试验证新标准的效果，根据测试结果调整

**Risk 2: 行业标准参照表可能不准确**
→ Mitigation: 邀请法律专家审核参照表，建立反馈机制持续更新

**Risk 3: 迁移过程中可能出现兼容性问题**
→ Mitigation: 保持 v2 版本可用，允许快速回滚

**Risk 4: 分层判定可能增加评价复杂度**
→ Mitigation: 简化判定逻辑，提供清晰的判定指南

**Trade-off: 灵活性 vs 一致性**
- 差异化标准提高了灵活性，但可能降低跨类型合同的一致性
- 通过通用标准层保持基础一致性

**Trade-off: 严格性 vs 通过率**
- 优化通用标准会降低严格性，但可以提高通过率
- 通过分层判定平衡两者
