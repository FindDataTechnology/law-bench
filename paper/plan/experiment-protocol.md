# 实验协议（Experiment Protocol）

> 硬门控产物：写实验章之前必须锁定。任何偏离本协议的结果陈述视为无效。

## 1. 数据集与划分

| 项 | 内容 |
|---|---|
| 评估集 | 43 类中文合同：19 类《民法典》典型有名合同 + 24 类无名合同 |
| 集合来源 | `src/contracts/classification.py`（NAMED_CONTRACTS / UNNAMED_CONTRACTS），与 `src/eval/seed/law_info/contract_types.json` 的 43 类子集、以及 86 份法律调研种子（doubao/deepseek 各 43）完全一致 |
| 口径声明 | `contract_types.json` 当前共 66 类，其中 23 类（婚姻家事、继承、担保物权、保密竞业、实习培训等）未参与本次评估，**不得计入任何结果数字** |
| 划分策略 | 不做训练/测试划分（非训练型系统）；全部 43 类均为评估对象 |
| 每类样本 | 每类 1 份合同草稿（由系统生成），以该类的评审项集合评分 |

## 2. 评估协议

| 项 | 内容 |
|---|---|
| 评审项 | 每类合同对应一套 rubric（`contract_<type>_v<N>`），逐条评审项独立裁判 |
| 裁判 | 每评审项 3 个裁判并发打分，判定 pass/fail |
| 聚合 | all-pass 二值：全部评审项通过得 1.0，否则 0.0；不存在部分得分 |
| 裁判置信度 | `FAIL_CONF_THRESHOLD`：0.99 = 仅全票失败触发改进；0.67 = 多数失败（2/3）即触发改进 |
| 裁判实现 | GEval（strict）式评审项裁判，见 `src/eval/scoring.py` |
| 生成温度 | 确定性填充 temperature 0 |
| 并发 | `EVAL_MAX_WORKERS=2` × 2 流 × 3 裁判 = 12 并发（经验安全上限，见第 5 节） |

## 4. 指标与聚合规则

| 指标 | 定义 | 聚合规则 |
|---|---|---|
| 全通过率 | 全评审项通过的合同类数 / 总类数 | 按具名/非具名分组报告，并给总通过率 |
| 逐类分数 | 通过评审项数 / 该类评审项总数 | 逐类报告，作为失败分析的依据 |
| 迭代轮次 | 达到全通过所需的自愈轮次 | 仅对通过类型报告 |

**多次运行说明**：现有结果为单次运行记录（自迭代过程本身含多轮）。论文须声明此点；若补多次运行，报告 mean ± std。

## 5. 工程配置与可复现性

| 项 | 值 |
|---|---|
| 并发上限 | 12（2 流 × 3 裁判 × 2 worker） |
| 限流特征 | 上游按账号（uid）而非按模型计量，3 个裁判后端共享同一限流桶 |
| 失败重试 | `_score_one` 对 429/503/ServiceUnavailable 重试 3 次（避免把限流噪声记为失败） |
| 条款更新策略 | 合并而非替换（`generate_combined_clause` 合并既有自定义条款与基础条款，避免内容损失） |
| 停机条件 | 达到全通过或达到轮次上限 |
