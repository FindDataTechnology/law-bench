## Why

The HTTP API server (`async-api-server`) ships with auto-generated OpenAPI/Swagger, but there's no standalone, human-readable API reference that developers can consume offline or embed in onboarding. The existing `docs/api-server.md` is a setup guide, not an endpoint reference, and the OpenAPI JSON itself is verbose and not browsable without a running server. This change creates a complete, accurate API reference document covering every endpoint's request schema, response schema, error codes, and worked examples — the canonical documentation contract for the API.

## What Changes

- **New API reference document**: A single comprehensive `docs/api-reference.md` documenting all 6 functional endpoints + health/docs, with method, path, auth, rate-limit, request body, response body, status codes, and curl examples for each.
- **Request/response schema tables**: Full field-by-field tables (name, type, required, default, description) for every Pydantic model derived from `api/schemas.py`.
- **Tag vocabulary reference**: A catalog of universal + representative type-specific tag dimensions (stance/scenario/strength/risk/mandatory + sale/lease/employment examples) so callers know valid tag values without querying.
- **Contract type catalog**: The full 43-type list with zh names, so callers know valid `contract_type` values.
- **Error catalog**: Every error response shape (401/403/404/422/429/500) with example bodies and the conditions that trigger each.
- **Cross-links**: Reference doc links to the existing `docs/api-server.md` (setup) and the live `/docs` (Swagger).
- **No code changes**: This is documentation-only; the API behavior is already implemented and tested.

## Capabilities

### New Capabilities

- `api-reference-docs`: Standalone, human-readable API reference documenting all endpoints, schemas, errors, tag vocabularies, and contract types for the HTTP API server.

### Modified Capabilities

None. The `http-api-server` capability (endpoint behavior) is unchanged; this change only documents it.

## Impact

**Affected Files**:
- New: `docs/api-reference.md` (comprehensive endpoint + schema reference)
- New: `docs/tag-vocabulary.md` (universal + type-specific tag dimension reference)
- Updated: `docs/api-server.md` (add cross-link to the new reference at the top)

**No code changes** — `api/schemas.py`, `api/routes/*.py`, and all behavior remain identical. Documentation is generated by hand from the implemented schemas to ensure accuracy.

**Dependencies**: None new. Markdown only.

**Verification**: The reference doc's schemas must match `api/schemas.py` field-for-field; a reviewer can diff the doc tables against the Pydantic models. Curl examples must be runnable against a locally-started server.
